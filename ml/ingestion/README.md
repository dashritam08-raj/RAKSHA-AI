# RAKSHA Real-Data Ingestion (Phase 5A)

This package creates a reproducible path from real observations to a reviewable ML training table.

## Sources

- Open-Meteo Historical Weather API for hourly historical weather variables.
- USGS Earthquake Catalog for earthquake events near monitored locations.
- NDMA SACHET remains a separate official-alert connector in the RAKSHA backend; it is not silently converted into a training target.

## 1. Configure monitoring locations

Start with `../data/locations_template.csv`. Replace the sample/template rows with your approved monitoring locations.

## 2. Fetch real historical observations

From the `ml` directory:

```powershell
python -m ingestion.fetch_environment `
  --locations data\locations_template.csv `
  --start-date 2024-01-01 `
  --end-date 2024-12-31 `
  --output-dir data\raw
```

Outputs:

- `data/raw/weather_observations.csv`
- `data/raw/earthquake_events.csv`
- `data/raw/ingestion_manifest.json`

## 3. Prepare reviewed incident labels

Copy `data/incident_labels_template.csv` to a new file and replace the placeholder values with real incident records and a domain-reviewed `target_risk_score`.

The target must be available as a documented outcome/label. Do not derive the target from the same environmental features used as predictors.

Then run:

```powershell
python -m ingestion.prepare_training_dataset `
  --incidents data\incident_labels_real.csv `
  --weather data\raw\weather_observations.csv `
  --earthquakes data\raw\earthquake_events.csv `
  --output data\processed\real_training_ready.csv
```

## Safety/data-quality rules

- No synthetic values are generated by these collectors.
- Weather matching uses the nearest available **prior** observation to prevent future-data leakage.
- Earthquake summaries use only events at or before the incident timestamp.
- Source URLs, timestamps and location identifiers are retained.
- A real-data table is not automatically promoted to a production ML model.
- Keep an untouched future period for final evaluation.
